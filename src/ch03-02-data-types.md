## Типы данных

Типы в Java делятся на две группы, и деление это — не формальность. От того, в
какой группе тип, зависит, что на самом деле лежит в переменной, как работает
сравнение и что произойдёт при передаче значения в метод.

**Примитивные типы** — числа, символы и логические значения. Переменная такого
типа хранит само значение.

**Ссылочные типы** — всё остальное: строки, массивы, объекты. Переменная хранит
не объект, а ссылку на него.

Разницу мы разбираем в главе 4 целиком. Здесь достаточно знать, что она есть.

## Целые числа

Целочисленных типов четыре, и различаются они только размером:

| Тип | Размер | Диапазон |
|---|---|---|
| `byte` | 8 бит | −128 … 127 |
| `short` | 16 бит | −32 768 … 32 767 |
| `int` | 32 бита | −2 147 483 648 … 2 147 483 647 |
| `long` | 64 бита | −9 223 372 036 854 775 808 … 9 223 372 036 854 775 807 |

Все они знаковые: беззнаковых целых в Java нет.

По умолчанию берите `int`. `byte` и `short` экономят память только в больших
массивах, а в одиночной переменной не экономят ничего — арифметика всё равно
идёт в `int`. `long` нужен, когда значения выходят за два миллиарда: деньги в
копейках, время в миллисекундах, счётчики событий.

Литерал `long` пишется с суффиксом `L`:

```java
void main() {
    long big = 10_000_000_000L;
    IO.println(big);
}
```

```text
10000000000
```

Подчёркивания в числе — разделители разрядов, компилятор их игнорирует.
`1_000_000` читается заметно лучше, чем `1000000`.

Без суффикса `L` эта же программа не соберётся: литерал `10000000000` считается
`int`, а в `int` такое число не помещается.

## Переполнение

А вот это стоит запомнить прочно:

```java,wrong_behavior
void main() {
    int max = Integer.MAX_VALUE;
    IO.println(max);
    IO.println(max + 1);
}
```

```text
2147483647
-2147483648
```

Прибавление единицы к максимальному значению даёт минимальное. Java **не**
сообщает о переполнении — ни ошибкой компиляции, ни исключением. Счётчик просто
переехал через край и продолжил с другого конца.

Это компилируется, не падает и молча выдаёт неверный результат — тот самый
третий случай. Классический способ на этом обжечься: вычислить середину
диапазона как `(low + high) / 2`. При больших значениях сумма переполняется, и
результат становится отрицательным. Эта ошибка много лет жила в стандартной
реализации двоичного поиска, прежде чем её заметили.

Когда переполнение недопустимо, используйте методы, которые о нём сообщают:

```java,throws
void main() {
    int max = Integer.MAX_VALUE;
    IO.println(Math.addExact(max, 1));
}
```

```text
Exception in thread "main" java.lang.ArithmeticException: integer overflow
```

`Math.addExact`, `multiplyExact` и родственные бросают исключение вместо того,
чтобы молча соврать. В коде, считающем деньги, это правильный выбор по
умолчанию.

## Вещественные числа

Их два: `float` (32 бита) и `double` (64 бита). Пишите `double`, если нет
причины поступить иначе; литерал без суффикса и так `double`.

Главное, что нужно знать о вещественных числах, — они неточны:

```java,wrong_behavior
void main() {
    IO.println(0.1 + 0.2);
    IO.println(0.1 + 0.2 == 0.3);
}
```

```text
0.30000000000000004
false
```

Это не баг Java. `double` хранит число в двоичной дроби, а 0.1 в двоичной
системе не представима точно — как 1/3 не представима в десятичной. Погрешность
накапливается, и точное сравнение перестаёт работать.

Отсюда два практических правила.

**Не сравнивайте вещественные числа через `==`.** Сравнивайте разность с
допуском: `Math.abs(a - b) < 1e-9`.

**Не считайте деньги в `double`.** Никогда. Для денег используют либо целые
числа в минимальных единицах (копейки, центы), либо класс `BigDecimal`, который
считает в десятичной системе и не имеет этой погрешности.

## Логический тип

`boolean` принимает ровно два значения: `true` и `false`. И всё — ничего больше
в него не положить и ни во что другое не превратить:

```java,does_not_compile
void main() {
    int x = 1;
    if (x) {
        IO.println("да");
    }
}
```

```text
error: incompatible types: int cannot be converted to boolean
    if (x) {
        ^
```

Если вы пришли из Python, JavaScript или C, это первое, обо что вы споткнётесь.
В Java **нет** истинности по умолчанию: ни ноль, ни пустая строка, ни `null` не
являются «ложными». Условие обязано быть `boolean`.

Неудобно ровно один раз — а взамен исчезает целый жанр ошибок, где `if (x = 1)`
вместо `if (x == 1)` компилируется и тихо делает не то. В Java такое
присваивание в условии не пройдёт проверку типов.

## Символы

`char` хранит один символ и записывается в одинарных кавычках. Двойные кавычки
— это строка, и это другой тип:

```java
void main() {
    char letter = 'A';
    IO.println(letter);
    IO.println(letter + 1);
    IO.println((char) (letter + 1));
}
```

```text
A
66
B
```

Вторая строка удивляет. `char` — это на самом деле число, код символа, и
арифметика с ним даёт `int`. Чтобы получить обратно символ, результат нужно
привести к `char` явно — это и делает `(char)` в третьей строке.

## Строки

`String` — ссылочный тип, а не примитив, и главное его свойство:
**строки неизменяемы**. Любой метод, который выглядит как изменяющий строку, на
самом деле возвращает новую:

```java
void main() {
    String greeting = "привет";
    greeting.toUpperCase();
    IO.println(greeting);
    IO.println(greeting.toUpperCase());
}
```

```text
привет
ПРИВЕТ
```

Вторая строка программы не делает ничего: результат `toUpperCase()` никуда не
записан и тут же выброшен. Это частая ошибка новичков, и компилятор о ней не
предупреждает.

Неизменяемость строк — сознательное решение, у которого много следствий: строку
можно безопасно передавать куда угодно, не опасаясь, что её испортят, и
использовать как ключ в справочниках. Подробности — в главах 4 и 11.

### Текстовые блоки

Многострочный текст раньше писали склейкой с `\n`, что читалось тяжело.
Начиная с Java 15 есть текстовые блоки:

```java
void main() {
    String text = """
        первая
        вторая""";
    IO.println(text);
}
```

```text
первая
вторая
```

Тройные кавычки открывают блок, отступ отсчитывается от самой левой непустой
строки — поэтому выравнивание в коде не попадает в результат.

> **Современный подход:** склейку длинного текста через `+` и `\n` стоит
> заменять текстовым блоком везде, где текст многострочный: SQL-запросы, JSON,
> HTML, сообщения об ошибках. Читается он ровно так, как выглядит, и в нём не
> нужно экранировать двойные кавычки — что для SQL и JSON решает половину
> проблемы.

## Приведение типов

Java автоматически расширяет тип, если это безопасно: `int` в `long`, `int` в
`double`. В обратную сторону — только явным приведением, потому что можно
потерять данные:

```java
void main() {
    int small = 42;
    long wide = small;
    IO.println(wide);

    double fraction = 3.99;
    int truncated = (int) fraction;
    IO.println(truncated);
}
```

```text
42
3
```

Приведение `double` к `int` **отбрасывает** дробную часть, а не округляет.
3.99 превращается в 3, −3.99 — в −3. Для округления есть `Math.round`.

## Коробочные типы

У каждого примитива есть парный класс-обёртка: `int` → `Integer`, `double` →
`Double`, `boolean` → `Boolean`. Нужны они там, где примитив не годится, —
прежде всего в коллекциях, которые умеют хранить только объекты.

Java преобразует между ними автоматически, и обычно об этом можно не думать.
Но одно следствие знать обязательно:

```java,wrong_behavior
void main() {
    Integer a = 127;
    Integer b = 127;
    IO.println(a == b);

    Integer c = 128;
    Integer d = 128;
    IO.println(c == d);
}
```

```text
true
false
```

Одинаковый код, разные числа, противоположные ответы. Дело в том, что `==` для
ссылочных типов сравнивает **ссылки**, а не значения, — а значения от −128 до
127 виртуальная машина кеширует и переиспользует. Два `127` оказываются одним и
тем же объектом, два `128` — разными.

Правильный ответ не в том, чтобы запомнить границу кеша, а в том, чтобы не
сравнивать объекты через `==`:

```java
void main() {
    Integer c = 128;
    Integer d = 128;
    IO.println(c.equals(d));
}
```

```text
true
```

Про `==` и `equals` будет отдельный разговор в главе 11. Пока правило простое:
примитивы сравнивают через `==`, объекты — через `equals`.
