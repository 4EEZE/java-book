# Приложение E — Версии Java

## Как устроены выпуски

С 2018 года Java выходит **каждые полгода**: в марте и сентябре. Раз в два года
один из выпусков объявляется **LTS** — с долгосрочной поддержкой.

Разница между ними не в содержимом, а в том, как долго выходят обновления
безопасности. Обычный выпуск поддерживается полгода, до следующего. LTS —
несколько лет.

| Версия | Вышла | Поддержка |
|---|---|---|
| 8 | 2014 | ещё жива, но пора уходить |
| 11 | 2018 | LTS |
| 17 | 2021 | LTS |
| **21** | сентябрь 2023 | LTS, основная поддержка до 2028 |
| **25** | сентябрь 2025 | LTS, основная поддержка до 2030 |
| 26 | март 2026 | обычный выпуск |
| 29 | сентябрь 2027 (план) | следующий LTS |

**Практическое правило: в рабочих проектах используйте LTS.** На момент
написания это Java 25 или, если обновление ещё не случилось, Java 21.

Обычные выпуски полезны, чтобы пробовать новое и заранее видеть, что придёт в
следующий LTS. Держать на них продакшен не стоит: через полгода обновления
кончатся.

## Обратная совместимость

Java известна тем, что почти не ломает существующий код. Программа,
скомпилированная десять лет назад, с большой вероятностью запустится на
сегодняшней виртуальной машине.

Это ценно и имеет цену. Ценно потому, что обновление версии обычно проходит
безболезненно, а огромная экосистема библиотек продолжает работать. Цена — в том,
что неудачные решения остаются навсегда: ковариантность массивов из главы 10,
стирание типов оттуда же, `null` из главы 4, `Stack`, наследующий `Vector`, из
главы 6.

Убрать их нельзя, не сломав миллионы программ. Поэтому язык развивается
добавлением: старое остаётся, рядом появляется лучшее.

## Что появилось когда

Список сокращённый — только то, что встречалось в книге.

**Java 5 (2004)** — обобщённые типы (глава 10), перечисления (глава 20),
аннотации (глава 20), цикл по элементам (глава 3), упаковка примитивов
автоматически.

**Java 7 (2011)** — `try` с ресурсами (глава 4), `switch` по строкам,
подчёркивания в числах, новый пакет для работы с файлами `java.nio.file`
(глава 16), перехват нескольких исключений одним `catch` (глава 9).

**Java 8 (2014)** — самый значимый выпуск. Лямбды (глава 14), потоки данных
(глава 15), `Optional` (глава 15), методы по умолчанию в интерфейсах (глава 6),
новый пакет для дат `java.time`.

**Java 9 (2017)** — модули (глава 17), `List.of` и родственные (глава 4),
`jshell`.

**Java 10 (2018)** — `var` для локальных переменных (глава 3).

**Java 11 (2018, LTS)** — запуск исходного файла напрямую (глава 1),
`Files.readString` и `writeString` (глава 16), встроенный `HttpClient`.

**Java 14–16** — текстовые блоки (глава 3), записи (глава 7), `instanceof` с
образцом (глава 6), `switch` как выражение (глава 3).

**Java 17 (2021, LTS)** — запечатанные типы (глава 7), обязательное строгое
поведение дробной арифметики.

**Java 18 (2022)** — UTF-8 кодировкой по умолчанию везде (глава 16).

**Java 21 (2023, LTS)** — виртуальные потоки (глава 19), сопоставление с
образцом в `switch` с разбором записей (глава 7).

**Java 25 (2025, LTS)** — компактные файлы с `void main()` без класса и класс
`IO` (глава 1).

## Как понять, что вам нужно

Полный список изменений каждой версии описан документами JEP — это предложения
по развитию платформы, каждое со своим номером. Например, компактные файлы из
главы 1 — это JEP 512.

Читать их целиком не нужно, но когда вы встречаете незнакомую возможность,
поиск по её названию вместе со словом JEP приводит к первоисточнику, где
объяснено не только что она делает, но и зачем понадобилась. Это часто
полезнее документации.
