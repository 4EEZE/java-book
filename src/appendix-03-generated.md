# Приложение C — Что язык пишет за вас

Часть кода компилятор создаёт сам. Знать, что именно, полезно: это избавляет от
лишней работы и объясняет, откуда берутся методы, которых вы не писали.

## У любого класса

Каждый класс наследует `Object` и получает его методы. Подробно они разобраны в
[главе 11](ch11-00-object-contracts.md).

| Метод | Поведение по умолчанию |
|---|---|
| `equals` | сравнивает ссылки, как `==` |
| `hashCode` | своё число у каждого объекта |
| `toString` | `ИмяКласса@хеш` |
| `getClass` | возвращает тип объекта |

Первые три почти всегда нужно переопределять — или брать запись, которая делает
это за вас.

Ещё компилятор добавляет **конструктор без аргументов**, если вы не объявили ни
одного своего. Объявите хоть один — бесплатный исчезнет, о чём мы говорили в
[главе 5](ch05-00-classes.md).

## У записи

Запись из [главы 7](ch07-00-records-and-patterns.md) получает готовым почти всё:

```java
public record Point(int x, int y) {}
```

| Что | Как выглядит |
|---|---|
| поля | `private final int x, y` |
| конструктор | `Point(int x, int y)` |
| методы доступа | `x()`, `y()` — без приставки `get` |
| `equals` | сравнение всех полей |
| `hashCode` | по всем полям, согласован с `equals` |
| `toString` | `Point[x=1, y=2]` |

Любой из них можно написать самому — тогда сгенерированного не будет. Чаще всего
переопределяют `toString`, а `equals` и `hashCode` трогать не стоит: сгенерированные
заведомо согласованы.

Отдельно — **компактный конструктор** для проверки и нормализации:

```java
public record Book(String title, int year) {
    public Book {
        if (year < -3000) throw new IllegalArgumentException("год: " + year);
        title = title.trim();
    }
}
```

У него нет списка параметров, и присваивание идёт **параметру**: поля компилятор
заполнит сам, уже очищенными значениями.

## У перечисления

Перечисление из [главы 20](ch20-00-advanced.md) получает:

| Что | Смысл |
|---|---|
| `values()` | массив всех вариантов |
| `valueOf(String)` | поиск по имени, исключение при неудаче |
| `name()` | имя варианта строкой |
| `ordinal()` | порядковый номер (хранить не стоит) |
| `compareTo` | сравнение по порядку объявления |
| `toString` | по умолчанию совпадает с `name()` |

Плюс само перечисление получает закрытый конструктор: новые варианты создать
нельзя.

## У интерфейса

Методы интерфейса по умолчанию `public abstract` — писать эти слова не нужно и
не принято:

```java
public interface Describable {
    String describe();              // public abstract подразумевается
}
```

Поля интерфейса автоматически `public static final`: интерфейс не может хранить
состояние, только константы.

## У лямбды

Лямбда из [главы 14](ch14-00-lambdas.md) — сокращение для реализации функционального интерфейса.
Компилятор выводит типы параметров из контекста и создаёт реализацию сам.

## Что компилятор вставляет незаметно

Несколько вещей, о которых полезно знать, встретив их в отладчике или
трассировке.

**Вызов `super()`** добавляется первой строкой конструктора, если вы не написали
ни `super(...)`, ни `this(...)` сами.

**Упаковка и распаковка** между `int` и `Integer` происходит автоматически —
отсюда и ловушка с кешем `Integer`, которую мы разбирали в [главе 3](ch03-00-common-concepts.md).

**Конкатенация строк** через `+` превращается в вызовы, собирающие строку
эффективно. Отдельный `StringBuilder` в обычном коде писать не нужно; он
пригождается только для склейки в цикле.

**Обход коллекции** через `for`-по-элементам разворачивается в работу с
обходчиком — именно поэтому изменение коллекции во время обхода даёт
`ConcurrentModificationException` из [главы 8](ch08-00-collections.md).

**Класс компактного файла** достраивается целиком: методы верхнего уровня
становятся его членами. Из-за этого `private` между классами в одном таком файле
ничего не закрывает — об этом была отдельная речь в главе 5.
