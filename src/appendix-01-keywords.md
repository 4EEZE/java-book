# Приложение A — Ключевые слова

В главе 3 мы обещали полный список. Вот он.

## Зарезервированные слова

Эти слова нельзя использовать как имена переменных, методов, классов и пакетов —
ни при каких условиях.

| | | | |
|---|---|---|---|
| `abstract` | `assert` | `boolean` | `break` |
| `byte` | `case` | `catch` | `char` |
| `class` | `const` | `continue` | `default` |
| `do` | `double` | `else` | `enum` |
| `extends` | `final` | `finally` | `float` |
| `for` | `goto` | `if` | `implements` |
| `import` | `instanceof` | `int` | `interface` |
| `long` | `native` | `new` | `package` |
| `private` | `protected` | `public` | `return` |
| `short` | `static` | `strictfp` | `super` |
| `switch` | `synchronized` | `this` | `throw` |
| `throws` | `transient` | `try` | `void` |
| `volatile` | `while` | | |

Отдельно стоят три **литерала** — `true`, `false` и `null`. Формально они не
ключевые слова, а значения, но использовать их как имена тоже нельзя.

## Слова, которые не используются

Два слова в списке зарезервированы, но в языке не применяются:

`goto` — команда безусловного перехода. Её зарезервировали в первой версии на
случай, если понадобится, и не добавили. Вместо неё — помеченные циклы из главы
3.

`const` — объявление константы. Эту роль занял `final`, а слово осталось занятым.

Смысл в том, чтобы их нельзя было использовать как имена: иначе добавление
такой возможности когда-нибудь сломало бы существующий код.

Ещё одно слово, `strictfp`, применялось до Java 17: оно требовало строгого
соответствия стандарту при вычислениях с дробными числами. С Java 17 такое
поведение стало обязательным везде, и слово потеряло смысл, оставшись
зарезервированным.

## Контекстные ключевые слова

А вот это удивляет. Следующие слова **можно** использовать как имена переменных:

```java
var record = 1;
var sealed = 2;
var yield = 3;
var when = 4;
var var = 5;
```

Компилируется. Всё перечисленное — **контекстные** ключевые слова: они имеют
особое значение только там, где это однозначно.

| Слово | Где значимо |
|---|---|
| `var` | вывод типа локальной переменной (глава 3) |
| `record` | объявление записи (глава 7) |
| `sealed`, `permits`, `non-sealed` | запечатанные типы (глава 7) |
| `yield` | возврат значения из ветки `switch` (глава 3) |
| `when` | страж в образце (глава 7) |
| `module`, `requires`, `exports`, `opens`, `provides`, `uses`, `to`, `with` | описание модуля (глава 17) |

Сделано это ради совместимости, и причина понятна. Если бы `record` стало
зарезервированным, весь существующий код с переменной или методом `record`
перестал бы компилироваться. А такого кода в мире немало.

Из этого следует практический вывод: компилятор не запрещает назвать переменную
`record`, но так делать не стоит. Читателя это собьёт, а рано или поздно
где-нибудь получится двусмысленность.

## Чего в Java нет

Несколько слов, которые ищут пришедшие из других языков.

**Нет `struct`** — для данных используют запись из главы 7.

**Нет `virtual` и `override`** — методы виртуальны по умолчанию, а `@Override`
из главы 6 является аннотацией, а не ключевым словом.

**Нет `readonly`** — эту роль играет `final`, помня ограничение из главы 4: он
фиксирует имя, а не содержимое.

**Нет `unsigned`** — беззнаковых целых в Java нет вовсе.

**Нет `async` и `await`** — вместо них виртуальные потоки из главы 19,
позволяющие писать обычный блокирующий код.
