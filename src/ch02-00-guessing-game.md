# Угадай число

Разберём язык руками, прежде чем разбирать его по частям. В этой главе мы
напишем небольшую программу целиком: она загадывает число от 1 до 100, а вы
пытаетесь его угадать, получая после каждой попытки подсказку — больше или
меньше.

По дороге нам встретятся переменные, ввод-вывод, ветвления, циклы и обработка
ошибок. Мы будем пользоваться ими, не углубляясь: подробный разбор каждой темы
ждёт в следующих главах. Задача этой — получить работающую программу и
почувствовать, как Java ощущается в деле.

Если вам неуютно писать код, не понимая каждую строчку, — пропустите эту главу
и вернитесь после третьей. Ничего не потеряете.

## Готовим место

```console
$ mkdir -p ~/projects/game
$ cd ~/projects/game
```

Создайте файл `game.java`. Начнём с малого — программа поздоровается:

<span class="filename">Файл: game.java</span>

```java
void main() {
    IO.println("Угадай число!");
}
```

```console
$ java game.java
Угадай число!
```

Работает. Будем наращивать.

## Читаем ввод

Чтобы игрок мог назвать вариант, программе нужно прочитать строку с клавиатуры.
В Java 25 для этого есть `IO.readln`:

<span class="filename">Файл: game.java</span>

```java
void main() {
    IO.println("Угадай число!");

    String ввод = IO.readln("Ваш вариант: ");
    IO.println("Вы назвали: " + ввод);
}
```

<span class="caption">Листинг 2-1. Читаем строку и печатаем её обратно</span>

Новых вещей здесь три.

`String ввод` — объявление **переменной**. Java требует указать тип: `String`
означает «строка текста». Тип пишется перед именем, и компилятор проследит,
чтобы в эту переменную не положили ничего, кроме строки.

`IO.readln("Ваш вариант: ")` печатает приглашение и ждёт, пока пользователь
введёт строку и нажмёт Enter. Введённое становится значением переменной.

`"Вы назвали: " + ввод` — **конкатенация**: плюс между строками склеивает их.
Мы вернёмся к этому в главе 3, где выяснится, что у плюса со строками есть
неприятная особенность.

Проверим:

```console
$ java game.java
Угадай число!
Ваш вариант: 42
Вы назвали: 42
```

## Загадываем число

Программе нужно число, которое игрок будет угадывать. Случайное число даёт
класс `Random`:

<span class="filename">Файл: game.java</span>

```java
import java.util.Random;

void main() {
    IO.println("Угадай число!");

    int загаданное = new Random().nextInt(1, 101);
    IO.println("(подсказка на время отладки: " + загаданное + ")");

    String ввод = IO.readln("Ваш вариант: ");
    IO.println("Вы назвали: " + ввод);
}
```

<span class="caption">Листинг 2-2. Загадываем число от 1 до 100</span>

`import java.util.Random;` в первой строке — мы сообщаем, что дальше в файле
слово `Random` означает класс `Random` из пакета `java.util`. Без этой строки
компилятор его не найдёт: в отличие от `String` и `IO`, которые доступны
всегда, `Random` живёт в другом пакете. Импорты всегда идут в начале файла.

`new Random()` создаёт объект-генератор. Ключевое слово `new` мы разберём в
главе 4 — пока достаточно, что так в Java создают объекты.

`nextInt(1, 101)` возвращает случайное число от 1 включительно до 101
**не** включительно, то есть от 1 до 100. Граница «не включая» кажется
странной, но это сквозное соглашение всей библиотеки Java, и привыкнуть к нему
придётся.

`int` — тип целого числа.

Подсказку с загаданным числом мы печатаем временно, чтобы не играть вслепую при
отладке. Перед тем как показывать программу кому-то, строку надо убрать — и это
не шутка: подобные отладочные строки регулярно доезжают до продакшена.

> **Современный подход:** двухаргументный `nextInt(1, 101)` появился только в
> Java 17. До него писали `nextInt(100) + 1` — «случайное от 0 до 99, плюс
> один». Эта запись до сих пор встречается повсеместно, и её полезно узнавать,
> но новый вариант читается лучше: в нём границы написаны прямо, а не
> получаются арифметикой в уме.

## Сравниваем

Теперь сравним введённое с загаданным. Проблема в том, что `IO.readln` вернул
**строку**, а `загаданное` — **число**, и сравнить их напрямую нельзя. Строку
нужно превратить в число:

```java
int вариант = Integer.parseInt(ввод);
```

`Integer.parseInt` разбирает строку и возвращает число. Что будет, если строка
числом не является, разберём чуть позже — сначала доведём до конца основную
логику.

<span class="filename">Файл: game.java</span>

```java
import java.util.Random;

void main() {
    IO.println("Угадай число!");

    int загаданное = new Random().nextInt(1, 101);

    String ввод = IO.readln("Ваш вариант: ");
    int вариант = Integer.parseInt(ввод);

    if (вариант < загаданное) {
        IO.println("Слишком мало!");
    } else if (вариант > загаданное) {
        IO.println("Слишком много!");
    } else {
        IO.println("Вы угадали!");
    }
}
```

<span class="caption">Листинг 2-3. Сравниваем вариант с загаданным числом</span>

Конструкция `if`/`else if`/`else` проверяет условия по порядку и выполняет
первую ветку, условие которой истинно. Условие обязано быть в круглых скобках —
компилятор на этом настаивает.

```console
$ java game.java
Угадай число!
Ваш вариант: 50
Слишком мало!
```

Одна попытка есть. Нужны все.

## Повторяем до победы

Обернём чтение и сравнение в цикл:

<span class="filename">Файл: game.java</span>

```java
import java.util.Random;

void main() {
    IO.println("Угадай число!");

    int загаданное = new Random().nextInt(1, 101);

    while (true) {
        String ввод = IO.readln("Ваш вариант: ");
        int вариант = Integer.parseInt(ввод);

        if (вариант < загаданное) {
            IO.println("Слишком мало!");
        } else if (вариант > загаданное) {
            IO.println("Слишком много!");
        } else {
            IO.println("Вы угадали!");
            break;
        }
    }
}
```

<span class="caption">Листинг 2-4. Цикл до правильного ответа</span>

`while (true)` — цикл, который сам по себе не закончится никогда. Выход из него
даёт `break` в ветке с угаданным числом: он немедленно прерывает цикл.

Бесконечный цикл с выходом изнутри — нормальная и частая конструкция, когда
число повторений заранее неизвестно. Главное — убедиться, что выход достижим.
Здесь он достижим: рано или поздно игрок назовёт нужное число.

```console
$ java game.java
Угадай число!
Ваш вариант: 50
Слишком мало!
Ваш вариант: 75
Слишком много!
Ваш вариант: 62
Вы угадали!
```

Игра работает. Осталось разобраться с тем, что будет, когда что-то пойдёт не
так, — а пойдёт обязательно.

## Когда ввели не число

Программа из листинга 2-4 компилируется и прекрасно работает — пока игрок
вводит числа. Попробуйте ввести что-нибудь другое:

```java,throws
int вариант = Integer.parseInt("абв");
```

```text
Угадай число!
Ваш вариант: абв
Exception in thread "main" java.lang.NumberFormatException: For input string: "абв"
	at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:67)
	at java.base/java.lang.Integer.parseInt(Integer.java:527)
	at java.base/java.lang.Integer.parseInt(Integer.java:624)
	at game.main(game.java:10)
```

Читается такая простыня сверху вниз, но полезна она снизу вверх. Последняя
строка — ваш код: файл `game.java`, строка 10. Всё, что выше, — внутренности
библиотеки, куда вы попали оттуда. В девяти случаях из десяти смотреть надо на
первую строку (что случилось) и на последнюю строку с вашим файлом (откуда).
Номера строк внутри `Integer.java` у вас будут другими — они зависят от версии
JDK.

`Integer.parseInt` не смог разобрать строку и выбросил **исключение**. Мы не
обработали его, поэтому программа аварийно завершилась.

Помните различие из первой главы? Это ошибка времени выполнения. Компилятор
пропустил код без замечаний: с точки зрения типов всё безупречно —
`Integer.parseInt` принимает строку, а мы дали строку. Вот только не всякая
строка является числом, и знать это заранее компилятор не мог.

Обработать исключение можно так:

```java
int вариант;
try {
    вариант = Integer.parseInt(ввод);
} catch (NumberFormatException e) {
    IO.println("Это не число, попробуйте ещё раз.");
    continue;
}
```

`try` означает «попробуй выполнить это». Если внутри выброшено исключение
указанного в `catch` типа, управление переходит в блок `catch`, а не обрушивает
программу.

`continue` переходит к следующей итерации цикла — то есть мы просто просим
ввести ещё раз.

Обратите внимание, что объявление `int вариант;` вынесено **до** `try`. Если
объявить переменную внутри блока, снаружи она будет не видна: в Java переменная
живёт только в тех фигурных скобках, где объявлена.

Исключениям целиком посвящена глава 9. Пока запомните форму `try`/`catch` — до
неё мы ещё вернёмся.

## Когда ввод закончился

Есть второй способ сломать программу, о котором обычно не думают. Запустите её
и нажмите Ctrl+D (на Windows — Ctrl+Z и Enter), то есть сообщите, что читать
больше нечего.

Программа не упадёт. Произойдёт кое-что похуже:

```java,wrong_behavior
while (true) {
    String ввод = IO.readln("Ваш вариант: ");

    int вариант;
    try {
        вариант = Integer.parseInt(ввод);
    } catch (NumberFormatException e) {
        IO.println("Это не число, попробуйте ещё раз.");
        continue;
    }
    // ...
}
```

```text
Угадай число!
Ваш вариант: Это не число, попробуйте ещё раз.
Ваш вариант: Это не число, попробуйте ещё раз.
Ваш вариант: Это не число, попробуйте ещё раз.
```

И так до бесконечности — на моей машине полтора миллиона строк за пять секунд,
пока не нажмёшь Ctrl+C.

Разберём, что произошло. Когда читать больше нечего, `IO.readln` возвращает
**`null`** — специальное значение, означающее «здесь ничего нет».
`Integer.parseInt(null)` действительно выбрасывает исключение, вот только
исключение это — `NumberFormatException` с текстом `Cannot parse null string`.
То самое, которое мы только что научились перехватывать.

Наш `catch` добросовестно его ловит, печатает «это не число» и через `continue`
идёт на новый круг. Читать по-прежнему нечего, `readln` снова возвращает `null`,
и всё повторяется. Цикл, из которого мы предусмотрели выход, стал бесконечным.

Обратите внимание, насколько эта ситуация неприятнее предыдущей. Программа
компилируется. Программа не падает. Программа даже печатает осмысленное
сообщение. Она просто не делает того, что нужно, — и заметит это только тот,
кто её запустит. Это третий из тех случаев, о которых мы говорили во введении,
и именно поэтому он помечен отдельным стикером.

Виновата здесь не `null`, а наша обработка ошибок. Мы написали «если не
разобралось в число — проси ввести ещё раз», молча предположив, что ввести
ещё раз всегда возможно. Перехват исключения превратил внятную аварию в тихое
неправильное поведение. Это общая беда широких `catch`, и в главе 9 мы вернёмся
к вопросу, что ловить стоит, а что лучше пропустить наверх.

Лечится проверкой до того, как мы вообще полезем разбирать строку:

```java
if (ввод == null) {
    IO.println("Ввод закончился. До встречи!");
    break;
}
```

Сравнение с `null` делается через `==` — это единственный случай, когда так
сравнивать правильно. Почему для всего остального `==` не годится, разберём в
главе 11.

## Готовая программа

<span class="filename">Файл: game.java</span>

```java
import java.util.Random;

void main() {
    IO.println("Угадай число от 1 до 100!");

    int загаданное = new Random().nextInt(1, 101);
    int попыток = 0;

    while (true) {
        String ввод = IO.readln("Ваш вариант: ");

        if (ввод == null) {
            IO.println("Ввод закончился. Я загадал " + загаданное + ".");
            break;
        }

        int вариант;
        try {
            вариант = Integer.parseInt(ввод.trim());
        } catch (NumberFormatException e) {
            IO.println("Это не число, попробуйте ещё раз.");
            continue;
        }

        попыток++;

        if (вариант < загаданное) {
            IO.println("Слишком мало!");
        } else if (вариант > загаданное) {
            IO.println("Слишком много!");
        } else {
            IO.println("Вы угадали за " + попыток + "! Число было " + загаданное + ".");
            break;
        }
    }
}
```

<span class="caption">Листинг 2-5. Игра целиком</span>

Две мелочи, которые появились здесь впервые.

`ввод.trim()` убирает пробелы по краям строки. Без этого ввод с лишним пробелом
не разобрался бы в число, и игрок получил бы «это не число» за то, что промазал
по клавише.

`попыток++` увеличивает переменную на единицу — короткая запись для
`попыток = попыток + 1`.

> **Под капотом:** а откуда `Random` берёт случайность? Из арифметики.
> Генератор хранит внутри число — состояние — и на каждый вызов пересчитывает
> его по формуле, выдавая очередной результат. Последовательность полностью
> определена начальным состоянием, поэтому такие числа называют
> **псевдослучайными**: задайте начальное состояние явно (`new Random(42)`) —
> и получите одну и ту же последовательность при каждом запуске. Для игры это
> неважно, а для тестов, наоборот, очень удобно. А вот для паролей и ключей
> `Random` не годится совсем: по нескольким выданным числам его состояние
> восстанавливается. Там нужен `SecureRandom`.

Кириллица в именах переменных, напомним, компилируется, но в настоящем коде так
не пишут — здесь она только чтобы не отвлекать вас на перевод в первой
работающей программе. Дальше в книге имена английские.

> **Получилось:** вы написали программу, которая читает ввод, принимает решения,
> повторяет действия и не падает от неверных данных. Вы встретили переменные и
> типы, `if`/`else`, цикл с `break` и `continue`, импорт, создание объекта через
> `new`, преобразование строки в число и обработку исключения через
> `try`/`catch`. И увидели два способа уронить программу тем, что компилятор
> пропустил: неразбираемой строкой и `null`.

Всё это мы использовали, не объясняя как следует. Теперь можно и объяснить —
начиная со следующей главы.
