# Приложение D — Инструменты разработчика

В JDK входит около тридцати программ. Большинство вы не откроете никогда, но
десяток стоит знать — особенно те, что пригождаются, когда что-то пошло не так.

## Повседневные

**`java`** — запускает программу. Умеет принимать и готовый класс, и исходный
файл напрямую, как мы делали всю книгу.

**`javac`** — компилятор. Полезные флаги: `-d` указывает, куда класть классы,
`-g` сохраняет имена локальных переменных (из-за отсутствия которых в [главе 4](ch04-00-references.md)
сообщение об ошибке показывало `<local1>` вместо имени), `-Xlint:all` включает
все предупреждения.

**`jshell`** — интерактивная оболочка. Запустите её и пишите выражения по
одному:

```console
$ jshell
jshell> "привет".toUpperCase()
$1 ==> "ПРИВЕТ"
```

Незаменима, чтобы быстро проверить, как ведёт себя незнакомый метод, не заводя
файл и не запуская сборку.

**`jar`** — работа с JAR-архивами: собрать, распаковать, посмотреть содержимое.

**`javadoc`** — собирает документацию из комментариев, о чём [приложение F](appendix-06-javadoc.md).

## Когда что-то пошло не так

Вот ради чего этот список и нужен.

**`jps`** показывает запущенные Java-процессы и их идентификаторы. С него
начинается работа с остальными инструментами.

**`jstack <pid>`** печатает, что прямо сейчас делает каждый поток. Первое
средство, когда программа перестала отвечать: в выводе видно, кто чего ждёт, и
взаимные блокировки из [главы 18](ch18-00-concurrency.md) он находит и помечает явно.

**`jmap -histo <pid>`** показывает, сколько объектов какого класса лежит в куче.
Первое средство при подозрении на утечку памяти из главы 4: если каких-то
объектов миллионы, причина обычно сразу понятна по имени класса.

**`jcmd <pid> <команда>`** — универсальный инструмент, постепенно заменяющий
остальные. `jcmd <pid> help` покажет, что он умеет для конкретного процесса.

**`jconsole`** — графическое окно с графиками памяти, потоков и загрузки
процессора. Удобно, когда надо просто посмотреть, что происходит.

**`jfr`** и Flight Recorder — запись подробного журнала работы программы с
малыми накладными расходами. Инструмент для разбора проблем с
производительностью в настоящей нагрузке.

**`javap`** показывает байт-код. В обычной работе не нужен, но бесценен, когда
хочется увидеть, во что компилятор превратил ваш код: `javap -c ИмяКласса`.

## Сборка и распространение

**`jlink`** собирает урезанный образ среды выполнения, содержащий только нужные
модули из [главы 17](ch17-00-modules.md). Вместо сотен мегабайт JDK получается несколько десятков.

**`jpackage`** делает из этого готовый установщик под конкретную систему.

**`jdeps`** показывает, от чего зависит ваш код, — полезно при переезде на
модули.

**`jwebserver`** — простейший файловый веб-сервер одной командой. Для отладки
подходит, для чего-то большего — нет.

## За пределами JDK

**IDE.** IntelliJ IDEA, VS Code с расширением для Java, Eclipse. Разница с
блокнотом для Java больше, чем для динамических языков: статическая типизация
даёт инструментам достаточно информации, чтобы честно переименовывать сущности
во всём проекте и находить все обращения.

**Отладчик** встроен в любую IDE. Научиться ставить точку останова и смотреть
значения переменных стоит раньше, чем привыкнуть отлаживать печатью.

**Сборщики** — Maven и Gradle из [главы 1](ch01-00-getting-started.md).

**Форматирование и проверки.** `google-java-format` или `spotless` приводят код
к единому виду, `Checkstyle`, `SpotBugs` и `Error Prone` находят подозрительные
места. `Error Prone` особенно полезен: он ловит именно те ошибки, о которых мы
говорили в книге, — вроде переопределённого `equals` без `hashCode`.
