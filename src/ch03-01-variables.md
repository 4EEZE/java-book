## Переменные и изменяемость

Переменная в Java объявляется указанием типа перед именем:

```java
void main() {
    int count = 5;
    IO.println(count);
}
```

Тип `int` здесь не подсказка и не документация — это обязательство, которое
проверяет компилятор. Положить в `count` строку не получится ни при каких
обстоятельствах.

По умолчанию переменную можно менять:

```java
void main() {
    int count = 5;
    IO.println(count);
    count = 6;
    IO.println(count);
}
```

```text
5
6
```

## Переменную нужно инициализировать

Java не даст прочитать переменную, в которую ещё ничего не положили:

```java,does_not_compile
void main() {
    int count;
    IO.println(count);
}
```

```text
error: variable count might not have been initialized
    IO.println(count);
               ^
```

Обратите внимание на формулировку: **might** not have been initialized —
«возможно, не была». Компилятор требует, чтобы значение было гарантированно
присвоено по всем путям выполнения. Если хотя бы одна ветка оставляет
переменную пустой, программа не соберётся:

```java,does_not_compile
void main() {
    int n = 2;
    int count;
    if (n > 1) {
        count = 5;
    }
    IO.println(count);
}
```

Нам-то видно, что `n` равно двум и присваивание случится. Компилятор в такие
рассуждения не пускается: ветки `else` нет — значит, путь без присваивания
существует.

Это называется **определённым присваиванием**, и оно закрывает целый класс
ошибок, которые в C приводили к чтению мусора из памяти.

Одно исключение всё же есть, и знать о нём полезно: если условие — **константное
выражение**, компилятор вычисляет его заранее. `if (2 > 1)` собирается без
возражений, потому что ветка заведомо выполняется. Более того, достаточно
написать `final int n = 2` — и `n > 1` тоже станет константным выражением, а
программа выше внезапно скомпилируется. Уберёте `final` — снова перестанет.

Объявить переменную отдельно от присваивания при этом можно — так мы и делали
в игре из второй главы:

```java
void main() {
    int count;
    count = 5;
    IO.println(count);
}
```

## `final`: переменная, которую нельзя переприсвоить

Пометьте переменную словом `final` — и компилятор запретит менять её после
первого присваивания:

```java,does_not_compile
void main() {
    final int count = 5;
    count = 6;
}
```

```text
error: cannot assign a value to final variable count
    count = 6;
    ^
```

Зачем это нужно, если можно просто не менять переменную? Затем же, зачем нужны
типы. `final` превращает намерение в проверяемое утверждение: читающий код
видит, что значение зафиксировано, и ему не нужно просматривать сорок строк
ниже в поисках переприсваивания.

Здесь важно понимать границу, и она в Java проходит не там, где ожидают
пришедшие из других языков.

> **Под капотом:** `final` фиксирует **переменную**, а не **объект**, на
> который она указывает. Если переменная хранит список, `final` запретит
> присвоить ей другой список — но не помешает добавить элементы в текущий.
> Разница станет понятной в главе 4, где мы разберём, что на самом деле хранится
> в переменной. Пока просто запомните: `final` — это про имя, а не про
> содержимое.

## `var`: тип выводит компилятор

Писать тип дважды в одной строке утомительно, особенно когда он длинный:

```java
HashMap<String, List<Integer>> index = new HashMap<String, List<Integer>>();
```

Начиная с Java 10 тип локальной переменной можно не писать — компилятор выведет
его из выражения справа:

```java
void main() {
    var name = "Аня";
    var age = 30;
    IO.println(name + ", " + age);
}
```

```text
Аня, 30
```

Это **не** динамическая типизация. Типы здесь есть и проверяются как обычно:
`name` имеет тип `String`, `age` — тип `int`, и присвоить `age` строку
по-прежнему нельзя. Разница только в том, кто написал тип — вы или компилятор.

> **Современный подход:** `var` в Java появился поздно, и отношение к нему до
> сих пор встречается настороженное — особенно у тех, кто помнит, во что
> превращается код на языках без проверки типов. Опасение здесь беспочвенно:
> `var` работает только для локальных переменных с явной инициализацией, тип
> вычисляется на этапе компиляции и никуда не девается.
>
> Разумное правило: используйте `var`, когда тип очевиден из правой части
> (`var list = new ArrayList<String>()`), и пишите тип явно, когда он неочевиден
> (`var result = process(data)` — что вернул `process`, читателю неясно).
> Цель — читаемость, а не экономия символов.

У `var` есть ограничения, о которые вы споткнётесь:

```java,does_not_compile
void main() {
    var count;
    count = 5;
}
```

Выводить тип не из чего, и компилятор прямо это объясняет:

```text
error: cannot infer type for local variable count
    var count;
        ^
  (cannot use 'var' on variable without initializer)
```

По той же причине не скомпилируется и `var x = null;`: у литерала `null` нет
типа, который можно было бы вывести.

## Область видимости

Переменная существует внутри тех фигурных скобок, где объявлена, и во всех
вложенных. За пределами блока её нет:

```java,does_not_compile
void main() {
    if (true) {
        int inner = 1;
    }
    IO.println(inner);
}
```

```text
error: cannot find symbol
    IO.println(inner);
               ^
  symbol:   variable inner
  location: class scope
```

(`class scope` здесь — имя класса, которое компилятор взял из имени файла
`scope.java`; у вас будет своё.)

Ровно с этим мы столкнулись во второй главе, когда выносили объявление
`int вариант;` наружу из блока `try`.

А вот поведение, которое удивляет пришедших из C++, JavaScript или Rust:

```java,does_not_compile
void main() {
    int value = 1;
    {
        int value = 2;
        IO.println(value);
    }
}
```

```text
error: variable value is already defined in method main()
        int value = 2;
            ^
```

**Java запрещает затенение локальных переменных.** Во многих языках объявление
во вложенном блоке создаёт новую переменную, временно перекрывающую внешнюю;
здесь это просто ошибка компиляции.

Решение сомнительное с точки зрения гибкости и очень удачное с точки зрения
чтения чужого кода: встретив имя внутри метода, вы знаете, что оно означает
одно и то же от объявления до конца метода. Читать код, не держа в голове
стопку перекрытий, заметно легче.

## Константы

Значение, которое не меняется за всё время работы программы и известно заранее,
принято объявлять вне метода:

```java
static final int MAX_ATTEMPTS = 100;

void main() {
    IO.println("Попыток: " + MAX_ATTEMPTS);
}
```

```text
Попыток: 100
```

`static` означает, что значение принадлежит программе целиком, а не какому-то
объекту (подробно — в главе 5). `final` запрещает его менять.

Имена констант по соглашению пишут заглавными буквами через подчёркивание:
`MAX_ATTEMPTS`, а не `maxAttempts`. Это единственное место в Java, где такой
стиль уместен: обычные переменные и методы называют `camelCase`, классы —
`PascalCase`.

Соглашения об именах в Java соблюдаются необычайно строго, и нарушать их не
стоит. Компилятор промолчит, а вот читающий ваш код человек споткнётся: он
привык, что заглавные буквы означают константу.
