## Методы

Метод — это именованный кусок кода, который можно вызвать. В других языках такое
называют функцией; в Java говорят «метод», потому что он всегда кому-то
принадлежит — классу или объекту.

```java
void main() {
    greet("Аня");
    greet("Борис");
}

void greet(String name) {
    IO.println("Привет, " + name + "!");
}
```

```text
Привет, Аня!
Привет, Борис!
```

Разберём объявление `void greet(String name)`.

`void` — тип возвращаемого значения, здесь «ничего не возвращает». Тип пишется
**перед** именем и обязателен всегда.

`greet` — имя. По соглашению `camelCase`, и по традиции глагол: метод что-то
делает.

`(String name)` — список параметров. У каждого указан тип. Пустые скобки
означают, что параметров нет.

Порядок объявления не важен: `greet` объявлен ниже `main`, но вызывается из
него без проблем. Компилятор сначала читает файл целиком.

## Возврат значения

Если метод что-то возвращает, вместо `void` пишут тип результата, а внутри
используют `return`:

```java
void main() {
    IO.println(square(4));
}

int square(int value) {
    return value * value;
}
```

```text
16
```

Компилятор проверяет, что значение возвращается по всем путям — ровно так же,
как с инициализацией переменных:

```java,does_not_compile
int abs(int value) {
    if (value < 0) {
        return -value;
    }
}
```

```text
error: missing return statement
}
^
```

Ветка, где `value` неотрицательно, ничего не возвращает — и программа не
соберётся, хотя человеку очевидно, чего не хватает.

## Параметры передаются по значению

Вот место, где ошибаются чаще всего, и не только новички. В Java **все**
параметры передаются по значению: метод получает копию.

```java
void main() {
    int number = 1;
    change(number);
    IO.println(number);
}

void change(int value) {
    value = 99;
}
```

```text
1
```

`change` изменил свою копию, оригинал не пострадал. Пока всё просто. Теперь
то же самое с массивом:

```java
void main() {
    int[] array = {1, 2, 3};
    change(array);
    IO.println(array[0]);
}

void change(int[] values) {
    values[0] = 99;
}
```

```text
99
```

Значение изменилось. Противоречия здесь нет, хотя выглядит именно так.

Правило по-прежнему то же: передаётся копия. Но переменная `array` хранит не
массив, а **ссылку** на него. Скопировали ссылку — и обе, исходная и копия,
указывают на один и тот же массив. Меняя элемент через копию ссылки, вы меняете
тот самый массив.

Проверить это можно так:

```java
void main() {
    int[] array = {1, 2, 3};
    replace(array);
    IO.println(array[0]);
}

void replace(int[] values) {
    values = new int[] {99, 99, 99};
}
```

```text
1
```

Здесь метод не меняет массив, а присваивает своей копии ссылки другой массив.
Оригинальная переменная как указывала на старый массив, так и указывает.

Эта разница — между «изменить то, на что указывает ссылка» и «перенаправить
ссылку» — лежит в основе половины недоразумений с Java. Глава 4 посвящена ей
целиком.

## Перегрузка

В одном классе может быть несколько методов с одинаковым именем, если они
различаются параметрами:

```java
void main() {
    IO.println(max(3, 7));
    IO.println(max(3.5, 7.1));
    IO.println(max(3, 7, 5));
}

int max(int a, int b) {
    return a > b ? a : b;
}

double max(double a, double b) {
    return a > b ? a : b;
}

int max(int a, int b, int c) {
    return max(max(a, b), c);
}
```

```text
7
7.1
7
```

Это называется **перегрузкой**. Компилятор выбирает подходящий вариант по типам
и количеству аргументов — на этапе компиляции, а не во время работы.

Различаться должны именно параметры. Два метода, отличающиеся только типом
возвращаемого значения, — ошибка компиляции: по вызову `max(3, 7)` невозможно
понять, какой из них имелся в виду.

`a > b ? a : b` в примере — **тернарный оператор**: если условие истинно, всё
выражение равно значению до двоеточия, иначе — после. Это выражение, а не
инструкция, поэтому его можно вернуть из `return`.

## Переменное число аргументов

Если количество аргументов заранее неизвестно, последний параметр можно
объявить с многоточием:

```java
void main() {
    IO.println(sum());
    IO.println(sum(1, 2, 3));
    IO.println(sum(1, 2, 3, 4, 5));
}

int sum(int... values) {
    int total = 0;
    for (int value : values) {
        total += value;
    }
    return total;
}
```

```text
0
6
15
```

Внутри метода `values` — обычный массив. Такой параметр должен быть последним и
единственным в списке.

> **Под капотом:** многоточие — синтаксический сахар. Компилятор превращает
> `sum(1, 2, 3)` в `sum(new int[] {1, 2, 3})`, то есть на каждый вызов
> создаётся массив. В горячем цикле это заметно, и поэтому в стандартной
> библиотеке часто встречаются перегрузки на один, два и три аргумента рядом с
> версией на многоточие — ровно чтобы не создавать массив в частых случаях.
