## Привет, мир!

JDK стоит — напишем первую программу. По традиции она печатает «Привет, мир!».

### Создаём файл

Создайте каталог для проектов книги и в нём каталог для этой программы:

```console
$ mkdir -p ~/projects/hello
$ cd ~/projects/hello
```

Создайте файл `hello.java` со следующим содержимым:

<span class="filename">Файл: hello.java</span>

```java
void main() {
    IO.println("Привет, мир!");
}
```

<span class="caption">Листинг 1-1. Программа, печатающая «Привет, мир!»</span>

Если вы когда-нибудь видели Java-код, вы сейчас, возможно, решили, что мы
что-то потеряли. Мы вернёмся к этому через минуту — сначала запустим.

### Запускаем

```console
$ java hello.java
Привет, мир!
```

Готово. Вы написали программу на Java.

Обратите внимание: мы не компилировали её отдельной командой. Начиная с Java 11
команда `java` умеет принимать на вход исходный файл — она компилирует его в
памяти и сразу запускает. Файлов `.class` на диске не появляется. Для маленьких
программ это удобно, и большую часть книги мы будем делать именно так.

> **Под капотом:** компиляция никуда не делась — просто её результат не
> сохраняется. `java hello.java` поднимает тот же компилятор, что и `javac`,
> складывает байт-код в память и отдаёт его виртуальной машине. Поэтому
> запуск исходника не быстрее обычного: он ровно такой же, только без записи
> на диск. И поэтому же ошибки компиляции вы увидите точно те же.

### Разбираем по частям

Программа состоит из трёх строк, и в каждой есть что обсудить.

```java
void main() {
```

`main` — метод, с которого начинается выполнение программы. Виртуальная машина
ищет метод именно с таким именем; назовите его `start` — и программа не
запустится.

`void` перед именем — тип того, что метод возвращает. `void` означает «ничего
не возвращает». В Java тип возвращаемого значения пишется всегда и всегда
перед именем метода.

Круглые скобки после имени — список параметров. Здесь он пустой.

Фигурные скобки ограничивают **тело** метода — то, что он делает. Открывающую
скобку в Java принято ставить на той же строке; это не требование компилятора,
а соглашение, но настолько общепринятое, что нарушать его не стоит.

```java
    IO.println("Привет, мир!");
```

Эта строка печатает текст. Разберём её справа налево.

`"Привет, мир!"` — строковый литерал. Строки в Java всегда в двойных кавычках;
одинарные — это символ, а не строка, и это разные типы.

`println` — метод, который печатает переданное значение и переводит строку. Его
родственник `print` печатает без перевода.

`IO` — место, где этот метод живёт. В Java любой метод кому-то принадлежит:
методов «самих по себе», как функций в Python или JavaScript, здесь не бывает.
`IO` — служебный класс для простого ввода-вывода, добавленный в Java 25 как раз
для того, чтобы первая программа новичка выглядела как первая программа
новичка.

Точка с запятой в конце обязательна. Она завершает **инструкцию** — законченное
действие. Java, в отличие от многих современных языков, не расставляет их за
вас, и компилятор будет напоминать об этом ровно до тех пор, пока вы не
привыкнете.

Отступ в четыре пробела — соглашение, как и скобка на той же строке.

### Чего мы не написали

Теперь к тому, что вас, возможно, смутило. Вот та же программа в том виде, в
каком вы почти наверняка встретите её в чужом коде:

<span class="filename">Файл: Hello.java</span>

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Привет, мир!");
    }
}
```

<span class="caption">Листинг 1-2. Та же программа в классическом виде</span>

```console
$ java Hello.java
Привет, мир!
```

Результат тот же. Разница — в церемонии, и её стоит разобрать сразу, потому что
встречаться она будет постоянно.

`public class Hello { ... }` — объявление **класса**. Исторически в Java весь
код обязан был лежать внутри класса: свободно стоящих методов язык не
допускает. Имя класса при этом должно совпадать с именем файла — отсюда
`Hello.java` с большой буквы.

`static` — метод принадлежит классу целиком, а не конкретному объекту. Пока
достаточно знать, что без `static` виртуальная машина метод `main` не найдёт: у
неё нет объекта, у которого его вызвать, — программа ведь ещё не началась.

`String[] args` — параметр: массив строк, аргументы командной строки. Их можно
не использовать, но в классической форме объявить обязаны.

`System.out.println` — то же, что `IO.println`, только подробнее: `System` —
класс, `out` — поток стандартного вывода внутри него, `println` — метод этого
потока.

Сравните два листинга. Во втором пять слов из шести не имеют отношения к тому,
что программа делает; они объясняют, *где* она живёт. Для программы в двадцать
строк это шум. Для программы в двадцать тысяч строк — ровно та структура,
которая позволяет в ней ориентироваться.

В Java 25 (JEP 512) короткая форма стала полноценной частью языка: компилятор
достраивает недостающий класс сам. Обе формы — Java, обе компилируются в один и
тот же байт-код.

В книге мы будем пользоваться короткой формой, пока речь идёт о самом языке, и
перейдём на полную в главе 5, когда классы станут не церемонией, а предметом
разговора. Чужой код вам придётся читать в основном в полной форме — поэтому и
показываем обе.

### Когда что-то сломалось

Программа из трёх строк ломается редко, но метко. Уберите точку с запятой:

```java,does_not_compile
void main() {
    IO.println("Привет, мир!")
}
```

Запустите снова:

```text
hello.java:2: error: ';' expected
    IO.println("Привет, мир!")
                              ^
1 error
error: compilation failed
```

Компилятор называет файл, номер строки, ставит `^` под местом проблемы и
говорит, чего ждал. Привыкайте читать эти сообщения целиком: в Java они,
как правило, точны, и первая же строка обычно содержит ответ.

Две ошибки, которые вы почти наверняка увидите в ближайшие дни:

**`class Hello is public, should be declared in a file named Hello.java`** —
имя публичного класса не совпало с именем файла. Это требование `javac`, и
регистр в нём тоже важен. Любопытно, что при запуске `java Hello.java` напрямую
такой проверки нет: запуск исходника работает и с несовпадающим именем, а
падает та же программа только тогда, когда вы впервые соберёте её через `javac`
или сборщик. Держите имена совпадающими с самого начала.

**`error: cannot find symbol`** с указанием на `IO` — у вас Java старше 25.
Проверьте `java -version`. Либо обновитесь, либо пишите `System.out.println`:
это работает во всех версиях.

### Ошибки бывают двух видов

Всё, что мы разбирали выше, — ошибки **компиляции**: программа не собралась и
не запускалась ни на секунду. Есть и второй вид, и разница между ними важнее,
чем кажется.

```java,throws
void main() {
    IO.println("Считаем среднее");
    int сумма = 0;
    int количество = 0;
    IO.println("Среднее: " + сумма / количество);
}
```

Этот код компилируется без единого замечания. Деление на ноль — совершенно
корректная запись с точки зрения синтаксиса и типов; компилятор не знает, что
в `количество` окажется ноль. Проблема обнаруживается при запуске:

```text
Считаем среднее
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at div.main(div.java:5)
```

Заметьте: первая строка успела напечататься. Программа работала, дошла до
пятой строки и там прервалась. Это **исключение** — ошибка времени выполнения.
Целая глава 9 посвящена тому, что с ними делать.

Пока запомните разницу. Ошибку компиляции вам находит компилятор, бесплатно и
до запуска. Ошибку времени выполнения находит тот, кто запустил программу, — в
худшем случае пользователь. Поэтому чем больше ошибок язык способен поймать на
первом этапе, тем лучше, и именно за это в Java платят статической типизацией.

Кстати, про имена переменных кириллицей: так писать можно — компилятор
принимает любые буквы, — но так не пишут. В коде, который увидит кто-то кроме
вас, имена английские.

> **Кодировка.** Если вместо «Привет, мир!» в консоли получилась
> абракадабра — почти наверняка это Windows и кодировка консоли. Начиная с Java
> 18 исходники и вывод по умолчанию в UTF-8, но старый терминал может
> интерпретировать байты по-своему. Помогает `chcp 65001` перед запуском или
> Windows Terminal вместо `cmd.exe`.

### Компиляция отдельно от запуска

Мы запустили `.java` файл напрямую, и это скрыло один шаг. Сделаем его явно —
пригодится для понимания следующего раздела:

```console
$ javac Hello.java
$ ls
Hello.class  Hello.java
$ java Hello
Привет, мир!
```

`javac` скомпилировал исходник в `Hello.class` — файл с **байт-кодом**. Это не
машинный код вашего процессора: это инструкции для виртуальной машины.

Затем `java Hello` запустил его. Обратите внимание на аргумент: `Hello`, без
расширения. Мы передаём не имя файла, а имя класса — виртуальная машина сама
ищет соответствующий `.class`.

Отсюда следует главное свойство Java, которое в 90-е продавали лозунгом «write
once, run anywhere»: `Hello.class` можно скопировать на другую машину с другой
операционной системой и другим процессором, и он там запустится. Компилируется
код один раз, а под конкретное железо его переводит уже JVM — в момент
исполнения и с учётом того, как программа реально себя ведёт.

Такой двухшаговый цикл — норма для настоящих проектов. Но вызывать `javac`
руками для проекта из сотни файлов никто не станет. Чем это делают — в
следующем разделе.
