## Установка

Для работы с Java нужен **JDK** — Java Development Kit. Это компилятор, набор
инструментов и сама виртуальная машина, которая будет исполнять ваши программы.

Вы могли встречать аббревиатуру **JRE** — Java Runtime Environment. Это только
виртуальная машина, без компилятора: её ставят тем, кто Java-программы
запускает, но не пишет. Нам нужен именно JDK.

### Какую версию ставить

Ставьте **последнюю LTS-версию**. LTS (long-term support) — это выпуски, которые
поддерживают несколько лет; именно их используют в проде. Новые выпуски Java
выходят каждые полгода, LTS — примерно раз в два года.

В книге используется **Java 25** и новее. Почти весь код заработает и на Java
21, но несколько примеров в первых главах опираются на возможности, которые
появились позже, — мы будем это отмечать.

### Какую сборку ставить

JDK — это спецификация, а собирают его многие. Все перечисленные сборки
собраны из одного и того же исходного кода OpenJDK и ведут себя одинаково;
различаются лицензией, набором платформ и тем, кто чинит баги.

- **Eclipse Temurin** — сборка от фонда Eclipse. Бесплатна для любого
  использования, доступна везде. Хороший выбор по умолчанию.
- **Amazon Corretto**, **Microsoft Build of OpenJDK**, **Azul Zulu**,
  **BellSoft Liberica** — то же самое от других вендоров.
- **Oracle JDK** — сборка от Oracle. Функционально тот же OpenJDK, но лицензия
  у него своя и со временем менялась. Если вы не обязаны использовать именно
  его — проще взять Temurin и не читать лицензионное соглашение.

> **Примечание:** если в вашей организации уже выбрана сборка — используйте её.
> Переносить код между сборками не нужно, он одинаковый.

### Установка

**Самый простой способ на Linux и macOS** — менеджер версий SDKMAN!. Он умеет
держать несколько JDK рядом и переключаться между ними, что рано или поздно
понадобится:

```console
$ curl -s "https://get.sdkman.io" | bash
$ source "$HOME/.sdkman/bin/sdkman-init.sh"
$ sdk install java 25-tem
```

`25-tem` здесь — версия 25, сборка Temurin. Посмотреть все доступные варианты:
`sdk list java`.

**На Windows** удобнее всего через winget:

```console
> winget install EclipseAdoptium.Temurin.25.JDK
```

**Через пакетный менеджер дистрибутива** — тоже рабочий вариант, если вас
устраивает версия, которую он предлагает:

```console
$ sudo apt install openjdk-25-jdk      # Debian, Ubuntu
$ sudo pacman -S jdk-openjdk           # Arch
$ brew install --cask temurin          # macOS
```

**Вручную** — скачать архив с сайта выбранного вендора, распаковать и добавить
его подкаталог `bin` в переменную `PATH`.

> **Современный подход:** ставить JDK системным пакетом — самый привычный
> способ и самый неудобный в перспективе. Рано или поздно вы окажетесь между
> проектом, который требует Java 17, и проектом на Java 25, а системный пакет
> даёт ровно одну версию на всю машину. Менеджер версий — SDKMAN!, `jenv`,
> `mise` — держит несколько JDK рядом и переключает их per-project. Поставить
> его стоит сразу: перетаскивать уже работающее окружение всегда неприятнее,
> чем начать с правильного.

### Проверка

Откройте терминал — новый, если вы только что ставили JDK, — и выполните:

```console
$ java -version
```

Вы должны увидеть что-то в этом роде:

```text
openjdk version "25.0.1" 2025-10-21
OpenJDK Runtime Environment Temurin-25.0.1+9 (build 25.0.1+9)
OpenJDK 64-Bit Server VM Temurin-25.0.1+9 (build 25.0.1+9, mixed mode)
```

Номер версии и имя сборки будут свои — важно, что команда вообще нашлась и
номер не меньше 25.

Проверьте заодно компилятор:

```console
$ javac -version
```

```text
javac 25.0.1
```

Если `java` находится, а `javac` — нет, у вас стоит JRE вместо JDK. Вернитесь
на шаг назад и поставьте JDK.

Если не находится ни то ни другое — почти всегда дело в `PATH`. На Linux и
macOS проверьте, что строка инициализации SDKMAN! есть в конфиге вашей оболочки
(`~/.bashrc`, `~/.zshrc`, `~/.config/fish/config.fish`). На Windows — что
каталог `bin` вашего JDK прописан в системной переменной `Path`, и что вы
открыли терминал заново: уже запущенные окна старое значение `PATH` не
обновляют.

### Редактор

Писать можно в чём угодно, но для Java разница между «редактором с подсветкой»
и «редактором, который понимает язык» ощутимее, чем в динамических языках:
статическая типизация даёт инструментам достаточно информации, чтобы честно
находить определения, переименовывать сущности во всём проекте и показывать
ошибки до компиляции. Не пользоваться этим — значит платить за типы и не
получать сдачи.

- **IntelliJ IDEA** — стандарт индустрии. Есть бесплатная Community Edition.
- **VS Code** с расширением Extension Pack for Java.
- **Eclipse**, **NetBeans** — свободные IDE с долгой историей.
- Любой редактор с поддержкой LSP — через языковой сервер `jdtls`.

Дальше в книге мы работаем из терминала: так видно, что происходит на самом
деле. Всё, что мы делаем в терминале, IDE потом сделает за вас одной кнопкой —
но лучше сначала понимать, какой именно.
