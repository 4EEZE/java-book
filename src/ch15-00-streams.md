# Stream API и `Optional`

Лямбды из прошлой главы сами по себе мало что дают. Их сила — в цепочках
действий над данными, и для этого в Java есть **потоки**.

## Задача

Возьмём список книг и найдём названия изданных до 1900 года, по алфавиту:

```java
record Book(String title, String author, int year) {}
```

Циклом это пишется так:

```java
List<String> old = new ArrayList<>();
for (Book book : books) {
    if (book.year() < 1900) {
        old.add(book.title());
    }
}
Collections.sort(old);
IO.println(old);
```

```text
[Бесы, Идиот]
```

Работает. Но посмотрите, сколько здесь служебного: заведён изменяемый список,
который существует только как накопитель; сортировка отдельной строкой уже после
цикла; и чтобы понять замысел, нужно прочитать всё целиком и удержать в голове.

Потоком то же самое записывается как последовательность шагов:

```java
List<String> old = books.stream()
    .filter(book -> book.year() < 1900)
    .map(Book::title)
    .sorted()
    .toList();
```

```text
[Бесы, Идиот]
```

Читается сверху вниз как описание: взять книги, оставить старые, взять названия,
отсортировать, собрать в список. Промежуточного списка нет, накопителя нет.

## Из чего состоит цепочка

У любой цепочки три части.

**Источник.** `books.stream()` для коллекции, `Stream.of(...)` для отдельных
значений, `Arrays.stream(массив)` для массива.

**Промежуточные операции** — превращают поток в другой поток, и их может быть
сколько угодно:

| Операция | Что делает |
|---|---|
| `filter` | оставляет подходящие |
| `map` | превращает каждый элемент в другой |
| `sorted` | сортирует |
| `distinct` | убирает повторы |
| `limit` / `skip` | берёт первые / пропускает первые |

**Терминальная операция** — завершает цепочку и выдаёт результат. Их тоже
несколько: `toList`, `count`, `findFirst`, `anyMatch`, `forEach`, `collect`.

Терминальная операция обязательна. Цепочка без неё **не делает ничего**:

```java,wrong_behavior
books.stream()
     .filter(book -> book.year() < 1900)
     .map(Book::title);
```

Ни одной книги не проверено, ни одного названия не взято, программа выполнила
ноль работы. Промежуточные операции **ленивы**: они только запоминают, что
нужно сделать, а работа начинается, когда придёт терминальная операция.

У ленивости есть и приятное следствие: цепочка не создаёт промежуточных
коллекций и не делает лишнего. `findFirst` после `filter` остановится на первом
подходящем элементе, а не проверит весь список.

## Поток одноразовый

```java,throws
Stream<String> stream = Stream.of("а", "б");
IO.println(stream.count());
IO.println(stream.count());
```

```text
2
Exception in thread "main" java.lang.IllegalStateException:
	stream has already been operated upon or closed
```

Поток — не коллекция. Это описание обработки, и выполняется оно один раз.
Нужен второй проход — заводите поток заново от источника.

Отсюда практическое следствие: поток не хранят в поле и не передают далеко.
Его создают и тут же используют.

## Сбор результата

`toList()` — самый частый способ завершить цепочку, но не единственный. За
остальными идут в класс `Collectors`:

```java
Map<String, Long> byAuthor = books.stream()
    .collect(Collectors.groupingBy(Book::author, Collectors.counting()));

IO.println(byAuthor);
```

```text
{Замятин=1, Достоевский=2}
```

`groupingBy` раскладывает элементы по ключу, а вторым аргументом принимает, что
делать с каждой группой: посчитать, собрать в список, просуммировать.

Порядок в выводе, напомним из [главы 8](ch08-00-collections.md), не обещан: получается обычный `HashMap`.

Склейка строк:

```java
String authors = books.stream()
    .map(Book::author)
    .distinct()
    .collect(Collectors.joining(", "));
```

```text
Достоевский, Замятин
```

Для чисел есть отдельные потоки — они не требуют упаковки в объекты и умеют
считать статистику:

```java
IO.println(books.stream().mapToInt(Book::year).summaryStatistics());
```

```text
IntSummaryStatistics{count=3, sum=5661, min=1869, average=1887.000000, max=1920}
```

## `Optional`

Некоторые операции могут ничего не найти:

```java
Optional<Book> found = books.stream()
    .filter(book -> book.year() > 1900)
    .findFirst();
```

`findFirst` не возвращает книгу. Он возвращает `Optional<Book>` — «книга или
ничего».

Это ответ на проблему из [главы 4](ch04-00-references.md). Метод, возвращающий `null`, ничего о себе не
сообщает: проверять результат надо всегда, а забыть проверку легко. `Optional`
говорит о возможном отсутствии **типом**, и не заметить это невозможно.

Пользоваться им следует так:

```java
IO.println(found.map(Book::title).orElse("не нашли"));
```

```text
Мы
```

```java
Optional<Book> missing = books.stream()
    .filter(book -> book.year() > 2000)
    .findFirst();

IO.println(missing.map(Book::title).orElse("не нашли"));
```

```text
не нашли
```

`map` применяет функцию, если значение есть, и ничего не делает, если его нет.
`orElse` подставляет запасное значение. Проверки `if` нигде не понадобилось.

Полезный набор:

| Метод | Что делает |
|---|---|
| `map` | преобразует значение, если оно есть |
| `filter` | оставляет значение, если подходит под условие |
| `orElse` | подставляет запасное значение |
| `orElseGet` | то же, но вычисляет запасное только при надобности |
| `orElseThrow` | бросает исключение, если значения нет |
| `ifPresent` | выполняет действие, если значение есть |
| `isEmpty` / `isPresent` | проверяет наличие |

Разница между `orElse` и `orElseGet` заметна, когда запасное значение дорого
получить: `orElse` вычисляет его **всегда**, даже когда оно не понадобится, а
`orElseGet` — только при отсутствии.

### Как не надо

```java,throws
Optional<Book> missing = books.stream()
    .filter(book -> book.year() > 2000)
    .findFirst();

Book book = missing.get();
```

```text
Exception in thread "main" java.util.NoSuchElementException: No value present
```

Метод `get()` выбрасывает исключение на пустом `Optional`. Использовать его —
значит вернуться ровно туда, откуда уходили: снова возможна авария, только
вместо `NullPointerException` теперь `NoSuchElementException`.

Так же бессмысленна связка `isPresent()` плюс `get()`: это переписанная проверка
на `null`, только длиннее. Если проверка нужна явно, есть `orElseThrow` — он
хотя бы честно называет намерение.

> **Современный подход:** `Optional` придуман как **тип возвращаемого значения**
> для методов, которые могут ничего не найти. Только для этого.
>
> Не делайте `Optional` полем класса: он не предназначен для хранения и не
> сериализуется. Не делайте его параметром метода — вызывающему придётся
> оборачивать значение, которое у него и так есть; лучше две перегрузки.
> И не заводите `Optional` для коллекции: пустой список уже означает «ничего
> нет», а `Optional<List<T>>` создаёт два разных способа сказать одно и то же.
>
> Коротко: `Optional` возвращают, а не хранят и не принимают.

## Когда поток не нужен

> **Под капотом:** потоки — не всегда лучше цикла, и вот в каких случаях
> обычный `for` предпочтительнее.
>
> **Когда нужен `break`.** В потоке его нет; приходится городить `takeWhile` или
> `findFirst` там, где цикл сказал бы прямо.
>
> **Когда меняется внешнее состояние.** Лямбда не может менять локальные
> переменные — мы разбирали это в [главе 14](ch14-00-lambdas.md). Обход этого ограничения через поля
> и массивы-обёртки даёт код хуже цикла.
>
> **Когда цепочка перестаёт читаться.** Три-четыре операции читаются отлично.
> Десять, с вложенными лямбдами на несколько строк, — хуже любого цикла.
>
> **В горячем коде на примитивах.** Простой `for` по массиву чисел быстрее
> потока; разница видна только в по-настоящему нагруженных местах, но она есть.
>
> И отдельно про `parallelStream()`: он выглядит как бесплатное ускорение, но
> им не является. На малых объёмах накладные расходы съедают выигрыш, а на
> общем изменяемом состоянии он даёт ошибки, которые почти невозможно
> воспроизвести. Без измерений его применять не стоит.

## Итоги

Вы умеете строить цепочки из источника, промежуточных
операций и терминальной, знаете, что промежуточные ленивы и без терминальной
ничего не происходит. Помните, что поток одноразовый. Умеете собирать
результат в список, группировать и склеивать через `Collectors`. Понимаете,
зачем нужен `Optional`, умеете обращаться с ним через `map` и `orElse` и
знаете, что `get()` сводит всю пользу на нет.
