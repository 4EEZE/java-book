# Приложение B — Операторы и символы

## Арифметика

| Оператор | Значение |
|---|---|
| `+` `-` `*` | сложение, вычитание, умножение |
| `/` | деление |
| `%` | остаток от деления |
| `++` `--` | увеличение и уменьшение на единицу |

Деление целых **отбрасывает** дробную часть, а не округляет:

```java
IO.println(5 / 2);      // 2
IO.println(5 % 2);      // 1
IO.println(-5 % 2);     // -1
```

Знак остатка совпадает со знаком делимого — это отличается от математического
определения и от поведения некоторых других языков.

Деление целого на ноль даёт `ArithmeticException`, а вещественного — нет:

```java
IO.println(5.0 / 0);    // Infinity
IO.println(0.0 / 0);    // NaN
```

`NaN` («не число») обладает свойством, о которое спотыкаются: он **не равен
самому себе**. Проверять его нужно через `Double.isNaN(x)`, а не через `==`.

Разница между `i++` и `++i` — в том, что возвращается:

```java
int i = 5;
IO.println(i++);        // 5, затем i становится 6
int j = 5;
IO.println(++j);        // 6, j уже 6
```

## Сравнение

| Оператор | Значение |
|---|---|
| `==` `!=` | равно, не равно |
| `<` `>` `<=` `>=` | меньше, больше и так далее |
| `instanceof` | проверка типа, в том числе с образцом |

Главное про `==` сказано в [главах 4](ch04-00-references.md) и 11: для примитивов он сравнивает значения,
для объектов — тождество ссылок. Объекты сравнивают через `equals`.

## Логика

| Оператор | Значение |
|---|---|
| `&&` | И с коротким замыканием |
| `\|\|` | ИЛИ с коротким замыканием |
| `!` | отрицание |
| `&` `\|` `^` | побитовые И, ИЛИ, исключающее ИЛИ |

**Короткое замыкание** означает, что правая часть не вычисляется, если результат
уже ясен:

```java
if (list != null && !list.isEmpty()) { ... }
```

Если `list` равен `null`, вторая проверка не выполнится — и `NullPointerException`
не случится. Замените `&&` на `&`, и обе части вычислятся всегда: программа
упадёт.

Это не стилистическая мелочь, а самый частый способ безопасно проверить объект
перед обращением к нему.

## Побитовые операции

| Оператор | Значение |
|---|---|
| `&` `\|` `^` | побитовые И, ИЛИ, исключающее ИЛИ |
| `~` | побитовое отрицание |
| `<<` | сдвиг влево |
| `>>` | сдвиг вправо с сохранением знака |
| `>>>` | сдвиг вправо с заполнением нулями |

Два оператора сдвига вправо различаются обращением со знаковым битом:

```java
IO.println(-8 >> 1);    // -4
IO.println(-8 >>> 1);   // 2147483644
```

`>>` сохраняет знак (сдвиг работает как деление на два), `>>>` заполняет слева
нулями, из-за чего отрицательное число превращается в большое положительное.
Оператора `<<<` не существует: при сдвиге влево различать нечего.

## Присваивание

| Оператор | Равносильно |
|---|---|
| `=` | присваивание |
| `+=` `-=` `*=` `/=` `%=` | `x = x + y` и так далее |
| `&=` `\|=` `^=` `<<=` `>>=` `>>>=` | то же для побитовых |

У составных операторов есть особенность: они **молча приводят тип**.

```java
int x = 5;
x += 1.5;       // компилируется, x становится 6
x = x + 1.5;    // ошибка компиляции
```

Первая строка содержит скрытое приведение `double` к `int` с потерей дробной
части. Вторая честно не компилируется. Об этом стоит знать, чтобы не удивляться.

## Литералы

```java
1_000_000       // подчёркивания для читаемости
0b1010          // двоичный литерал: 10
0x1F            // шестнадцатеричный: 31
017             // ВОСЬМЕРИЧНЫЙ: 15, а не 17
100L            // long
1.5f            // float
'\n' '\t' '\\'  // управляющие последовательности
"""..."""       // текстовый блок (глава 3)
```

Восьмеричные литералы — ловушка, оставшаяся из C: ведущий ноль меняет систему
счисления. Код вроде `int month = 08;` не скомпилируется вовсе, потому что
восьмёрки в восьмеричной системе нет.
