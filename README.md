# О книге

Книга о Java на русском языке: 22 главы, 6 приложений, 40 тысяч слов и 144
интерактивных вопроса, встроенных прямо в текст.

Устроена по образцу [экспериментального издания The Rust Book][rustbook] от
Brown University — с квизами после разделов, стикерами у «плохих» примеров кода
и врезками. Только про Java.

[rustbook]: https://rust-book.cs.brown.edu/

---

## На чём основана

### Книга-образец

[The Rust Programming Language: Experimental Edition][rustbook] — форк
официальной книги по Rust, сделанный Cognitive Engineering Lab в Brown
University. В нём к тексту добавлены интерактивные квизы.

Из неё взято:

- **квизы после разделов** — движок `mdbook-quiz` тех же авторов;
- **стикеры у блоков кода**, предупреждающие, что пример не должен работать;
- **врезки** с полезным, но необязательным материалом;
- **чередование глав**: теоретические перемежаются проектными, где программа
  пишется целиком.

Технические вещи, специфичные для Rust, отброшены: Aquascope (визуализатор
borrow checker), препроцессоры оформления листингов, телеметрия.

### Исследование

Авторы книги-образца не просто добавили квизы — они собрали на них данные и
опубликовали работу:

> Will Crichton, Shriram Krishnamurthi. **Profiling Programming Language
> Learning.** Proceedings of the ACM on Programming Languages, Vol. 8, OOPSLA1,
> 2024. [doi:10.1145/3649812](https://doi.org/10.1145/3649812) — Distinguished
> Paper.

За 13 месяцев 62 526 читателей дали 1 140 202 ответа. Выводы применены к этой
книге напрямую.

**Главный: вопросы «скомпилируется ли эта программа?» — плохие.** Тематический
анализ показал, что среди 20 худших по дискриминации вопросов шесть были именно
такого формата, а среди 20 лучших — ни одного. Вывод статьи дословно: *«we can
likely rule out "does-it-compile" questions»*. Такой вопрос проверяет
внимательность, а не понимание.

Поэтому здесь ни одного вопроса в формате «скомпилируется?». Вместо него —
«программа не компилируется, а почему именно» с правдоподобными вариантами. Семь
вопросов, написанных до прочтения статьи, были переделаны.

**Второй: провальный вопрос обычно означает дефект текста, а не вопроса.** Самые
результативные правки в исследовании были там, где вопрос проверял то, о чём в
разделе прямо не говорилось (средний прирост по 12 вмешательствам — плюс 20%).
Данных читателей здесь нет, поэтому проверяется первопричина: скрипт
`check-quizzes.py` сверяет, что всё упомянутое в ответах проговорено в тексте
раздела.

**Третий: схемы.** Одно из лучших вмешательств у них — исправление диаграммы, на
которой не был показан один из сравниваемых случаев. По этому образцу в главе о
памяти добавлена схема пула строк, показывающая оба состояния рядом.

**Четвёртый: краткость.** Медиана времени на ответ — 29 секунд. Медиана длины
вопроса здесь 268 символов.

**Структура.** С чего начать → проектная глава «Угадай число» → основы языка →
объекты, ссылки и память → классы, интерфейсы, записи и образцы → коллекции,
исключения, обобщённые типы, контракты, тесты → проектная глава про программу
командной строки → лямбды и потоки данных → файлы, модули, многопоточность,
виртуальные потоки → финальный проект: многопоточный HTTP-сервер с нуля.

**Java 25+.** Книга описывает язык таким, какой он сейчас: записи, запечатанные
типы, сопоставление с образцом, виртуальные потоки, компактные файлы с
`void main()` без класса. Проверялась на JDK 26.

### Стикеры у кода

Блок кода помечается классом в info-строке ограды, и скрипт вешает картинку:

````markdown
```java,does_not_compile
```java,throws
```java,wrong_behavior
````

Три случая различаются намеренно, и разница объяснена во введении: не
скомпилировалось — компилятор сказал сам; упало с исключением — программа
сообщила; работает не так, как задумано — не сообщил никто, и это худший случай.
В тексте 25 / 12 / 21 соответственно.

### Врезки

Обычная цитата, начинающаяся с жирного слова-маркера:

```markdown
> **Современный подход:** так на Java пишут сейчас, а вот так писали раньше.
> **Под капотом:** как устроено уровнем ниже; для работы знать не обязательно.
```

Сводка в конце главы — не врезка, а обычный раздел `## Итоги` после квиза, как
`## Summary` в книге-образце.

## Сборка

Нужны два бинарника: `mdbook` и форк `mdbook-quiz`.

**mdBook** — готовая сборка с GitHub:

```console
$ V=$(curl -sL https://api.github.com/repos/rust-lang/mdBook/releases/latest \
      | grep -m1 '"tag_name"' | cut -d'"' -f4)
$ curl -sL "https://github.com/rust-lang/mdBook/releases/download/$V/mdbook-$V-x86_64-unknown-linux-gnu.tar.gz" \
      | tar xz -C ~/.local/bin
```

**mdbook-quiz** — локализованный форк в `tools/mdbook-quiz-ru`:

```console
$ cd tools/mdbook-quiz-ru
$ cargo test -p mdbook-quiz-schema --locked export_bindings --features ts
$ mkdir -p js/packages/quiz/src/bindings
$ cp crates/mdbook-quiz-schema/bindings/* js/packages/quiz/src/bindings/
$ cd js && npx pnpm@9 install
$ cd packages/quiz-embed && npx pnpm@9 exec vite build --mode production
$ cd ../../.. && cargo install --path crates/mdbook-quiz --locked
```

Фичи `rust-editor` и `aquascope` не включаются: они тянут Monaco и nightly
`rustc` и для книги про Java бесполезны.

Затем:

```console
$ mdbook serve --open
```

### Публикация

В `.github/workflows/pages.yml` лежит сборка для GitHub Actions: она ставит JDK,
собирает форк квизов, строит книгу, прогоняет проверки и публикует результат на
GitHub Pages.

Шаг публикации включается автоматически, когда репозиторий публичный: на
бесплатном тарифе GitHub Pages для приватных репозиториев недоступны. Пока
репозиторий закрыт, сборка всё равно запускается и работает как проверка —
прогоняет все 144 вопроса через валидатор и тесты оформления.

Чтобы публикация заработала, нужно сделать репозиторий публичным (или перейти на
тариф с поддержкой Pages) и в `Settings → Pages` выбрать источником
**GitHub Actions**.

### Проверки

```console
$ python3 check-quizzes.py                       # правила из исследования
$ python3 check-code.py                          # стикеры не врут
$ mdbook build && node theme/stickers.test.cjs   # механизм стикеров
```

`check-code.py` вынимает из текста все законченные программы и запускает их,
сверяя поведение с обещанием стикера: без стикера — работает, `does_not_compile`
— не собирается, `throws` — падает, `wrong_behavior` — собирается и работает.
Проверка нашла две настоящие ошибки: непомеченный блок, который бросал
исключение, и блок с пометкой «работает не то», который на деле падал с
`ClassCastException`.

Кроме того, валидатор внутри форка при **каждой** сборке книги компилирует и
запускает программу из каждого вопроса на предсказание вывода и сверяет
результат с записанным ответом. Неверный ответ роняет сборку. Он ловил ошибки
несколько раз.

## Чем форк отличается от оригинального mdbook-quiz

- интерфейс переведён на русский, включая склонение по числу («1 вопрос»,
  «2 вопроса», «5 вопросов»);
- подсветка кода в квизах по умолчанию Java вместо Rust;
- **валидатор переведён с `rustc` на `java`** — это он проверяет ответы запуском;
- исправлена паника в валидаторе: `cxensure!` не прерывает проверку, и при
  `doesCompile = true` без `stdout` оригинал падал на `unwrap()`;
- пояснение к полноэкранному режиму переписано: оригинальное описывало условия
  исследования с телеметрией, которой здесь нет.

Форк сохраняет исходные лицензии (MIT / Apache-2.0) и файлы `LICENSE-*`.
